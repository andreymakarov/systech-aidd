# ADR-006: OpenRouter как провайдер LLM

## Статус

Принято (Accepted)

## Контекст

Необходимо выбрать способ доступа к LLM моделям. Основные варианты:
1. Прямая интеграция с провайдерами (OpenAI, Anthropic, и т.д.)
2. Унифицированный провайдер (OpenRouter, LiteLLM)
3. Локальные модели (Ollama, LM Studio)

## Решение

Использовать **OpenRouter** как единый провайдер доступа к LLM моделям.

### Характеристики

- **URL:** https://openrouter.ai/api/v1
- **Совместимость:** OpenAI API (используем официальный `openai` клиент)
- **Модель по умолчанию:** `openai/gpt-4o-mini`
- **Конфигурация:** через переменную окружения `OPENROUTER_MODEL`

### Обоснование

1. **Единый интерфейс** для доступа к множеству моделей:
   - OpenAI (GPT-4, GPT-3.5)
   - Anthropic (Claude)
   - Google (Gemini)
   - Meta (Llama)
   - И другие

2. **Гибкое ценообразование**
   - Pay-as-you-go без подписок
   - Конкурентные цены
   - Выбор между скоростью и стоимостью

3. **Простота смены модели**
   - Меняем только переменную окружения
   - Не нужно переписывать код
   - Один API ключ для всех моделей

4. **Совместимость с OpenAI API**
   - Используем стандартный `openai` Python клиент
   - Только меняем `base_url`
   - Возможность легко переключиться на прямую интеграцию

## Последствия

### Положительные
- ✅ Гибкость выбора модели без изменения кода
- ✅ Возможность A/B тестирования разных моделей
- ✅ Один API ключ вместо множества
- ✅ Простая миграция на другого провайдера при необходимости
- ✅ Конкурентное ценообразование
- ✅ Доступ к новым моделям сразу после их появления

### Отрицательные
- ⚠️ Зависимость от стороннего сервиса (OpenRouter)
- ⚠️ Дополнительная задержка (проксирование через OpenRouter)
- ⚠️ Потенциальные проблемы с доступностью OpenRouter

### Риски и митигация

**Риск:** OpenRouter может быть недоступен  
**Митигация:** Легко переключиться на прямую интеграцию (меняем base_url)

**Риск:** Изменение цен или API  
**Митигация:** OpenRouter следует OpenAI стандарту, низкая вероятность breaking changes

### Выбор модели по умолчанию

**GPT-4o Mini** выбран как баланс между:
- Качеством ответов
- Стоимостью
- Скоростью генерации

Легко меняется через `.env` файл.

## Альтернативы

1. **Прямая интеграция с OpenAI** - отклонена (меньше гибкости, дороже)
2. **Прямая интеграция с Anthropic** - отклонена (нужен отдельный клиент)
3. **LiteLLM** - отклонена (требует дополнительного слоя/сервиса)
4. **Локальные модели (Ollama)** - отклонены (сложность развертывания, требования к железу)
