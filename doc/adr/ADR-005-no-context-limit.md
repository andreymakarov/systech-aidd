# ADR-005: Отсутствие ограничения контекста диалога

## Статус

Принято (Accepted)

## Контекст

История диалога с LLM может быть очень длинной. Необходимо решить:
- Ограничивать ли количество сообщений в контексте?
- Хранить всю историю диалога или только последние N сообщений?

Ограничения влияют на:
- Стоимость API запросов (больше токенов = дороже)
- Качество ответов (больше контекста = лучше понимание)
- Использование памяти

## Решение

**Не ограничивать** количество сообщений в истории диалога для каждого пользователя.

### Характеристики

- Вся история сессии отправляется в LLM
- Контекст ограничен только лимитами самой модели
- Пользователь может очистить историю командой `/clear`

### Обоснование для MVP

1. **Простота реализации** - не нужна логика обрезки истории
2. **Лучшее качество ответов** - модель видит весь контекст
3. **Малое количество пользователей** - стоимость не критична
4. **Пользователь сам контролирует** - через `/clear`

## Последствия

### Положительные
- ✅ Максимально простая реализация
- ✅ LLM имеет полный контекст диалога
- ✅ Лучшее качество и связность ответов
- ✅ Нет потери важной информации из начала диалога

### Отрицательные
- ⚠️ Растущая стоимость запросов при длинных диалогах
- ⚠️ Возможность превышения лимита контекста модели
- ⚠️ Увеличенное использование RAM
- ⚠️ Более медленные ответы при очень длинной истории

### Риски и митигация

**Риск:** Превышение context window модели  
**Митигация:** Модель вернет ошибку, пользователь использует `/clear`

**Риск:** Высокая стоимость API  
**Митигация:** Для MVP с малым количеством пользователей не критично

**Риск:** Медленные ответы  
**Митигация:** Пользователь может использовать `/clear` для сброса

### Возможность изменения

В будущем легко добавить:
- Автоматическое ограничение (например, последние 20 сообщений)
- Умная обрезка (summarization старых сообщений)
- Конфигурируемый лимит через переменную окружения
- Предупреждение пользователю о размере контекста

## Альтернативы

1. **Фиксированный лимит (10-20 сообщений)** - отклонено как преждевременная оптимизация
2. **Скользящее окно** - отклонено как избыточное усложнение для MVP
3. **Summarization** - отклонено как слишком сложное для MVP
