### FE-S01 — Требования к дашборду и Mock API

- Цели:
  - Определить функциональные требования к дашборду статистики диалогов (без доработок бэкенда).
  - Спроектировать KISS-контракт API (один метод получения агрегированной статистики под UI).
  - Спроектировать интерфейс `StatCollector` с реализациями: Mock и Real (позже).
  - Подготовить Mock-реализацию и автогенерацию документации.
  - Создать entrypoint и команды запуска/тестирования API.
- Описание состава работ:
  - Требования к UI дашборда; контракт API; интерфейс и Mock-реализация; документация; команды.
- Статус: ✅ Completed
- Дата завершения: 2025-10-17
- Ссылка на план: [План спринта](@FE-S01-mock-api-plan.md )
- Итоговая реализация (кратко):
  - Отдельный FastAPI-сервис на порту 8081 с базовым путём `/api`.
  - Метод `GET /api/stats?period=day|week|month` (регистронезависимый).
  - Интерфейс `StatCollector` и `MockStatCollector` с реалистичными данными.
  - Контракт в виде Pydantic-моделей + внутренние dataclasses.
  - Автогенерация OpenAPI/Swagger (`/docs`, `/openapi.json`).
  - Команды в Makefile: `run-stats-api`, `test-stats-api`, включение в `qa`.
