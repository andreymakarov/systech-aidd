# Идея проекта: Ролевой LLM-ассистент

## Описание проекта

Полноценный AI-продукт, реализованный в виде Telegram-бота с четко определенной ролью и специализацией.

## Эволюция проекта

Проект эволюционирует от базового LLM-ассистента к специализированному AI-продукту:
- **v1**: Базовый ассистент с системным промптом
- **v2**: Ролевой ассистент с конкретной функцией и специализацией

## Основные задачи

Основной задачей бота является качественное выполнение своей четко определенной роли через:
- Ведение диалога с пользователем в контексте роли
- Предоставление экспертных ответов в своей области
- Консистентное поведение согласно заданной роли

## Ключевые особенности

- **Платформа**: Telegram Bot
- **Технология**: Large Language Model (LLM)
- **Функционал**: Интерактивный диалог с пользователем в рамках роли
- **Специализация**: Конкретная роль с четко определенной функцией
- **Настройка**: Роль определяется через системный промпт, хранящийся в файле
- **Прозрачность**: Пользователь может посмотреть роль бота через команду `/role`

## Концепция роли

### Что такое роль
Роль - это четко определенная специализация ассистента, которая включает:
- **Экспертную область** - в чем ассистент является специалистом
- **Функции** - какие конкретные задачи он решает
- **Стиль общения** - как он взаимодействует с пользователем
- **Ограничения** - что он НЕ делает (вне его роли)

### Примеры ролей
- **Python-эксперт**: Помощь в написании и отладке Python кода
- **Бизнес-аналитик**: Анализ бизнес-процессов и требований
- **Технический писатель**: Создание документации и технических текстов
- **DevOps-консультант**: Помощь в настройке CI/CD и инфраструктуры

### Преимущества ролевой модели
1. **Качество**: Узкая специализация дает более качественные ответы
2. **Консистентность**: Последовательное поведение в рамках роли
3. **Ожидания**: Пользователь понимает что ожидать от ассистента
4. **Фокус**: Избегание размытых и неконкретных ответов

## Архитектура

Бот работает как интерфейс между пользователем в Telegram и LLM-моделью, передавая сообщения пользователя в модель и возвращая ответы обратно в чат.

## Технические детали

### Компоненты системы

1. **Telegram Bot API** - интерфейс для взаимодействия с пользователями
2. **LLM-модель** - языковая модель для генерации ответов
3. **Файл с системным промптом** - текстовый файл, определяющий роль и поведение бота
4. **Менеджер ролей** - компонент для загрузки и управления ролью бота

### Хранение системного промпта

**Формат**: Системный промпт хранится в отдельном текстовом файле (например, `prompts/role.txt`)

**Преимущества файлового хранения**:
- Легкая модификация роли без изменения кода
- Версионирование промптов через Git
- Возможность A/B тестирования разных версий промптов
- Переиспользование промптов между проектами
- Возможность динамической смены роли без перезапуска бота

**Структура промпта**:
```
Ты - [Название роли]

Твоя основная задача:
[Описание основной функции]

Твои обязанности:
- [Обязанность 1]
- [Обязанность 2]
- [Обязанность 3]

Стиль общения:
[Описание стиля]

Ограничения:
- [Что НЕ делать]
```

### Команды бота

#### `/start`
Приветственное сообщение с кратким описанием роли бота

#### `/role`
Отображает текущую роль бота - показывает пользователю системный промпт или его краткую версию, чтобы пользователь понимал с кем он общается и что может ожидать

**Пример вывода**:
```
🎭 Моя роль: Python-эксперт

Я специализируюсь на:
• Помощь в написании Python кода
• Отладка и оптимизация кода
• Объяснение концепций Python
• Рекомендации по best practices

Я НЕ занимаюсь:
• Задачами вне Python разработки
• Написанием кода на других языках
```

#### `/clear`
Очистка истории диалога (существующая функция)

### Процесс работы

1. **Инициализация**: При запуске бот загружает системный промпт из файла
2. **Получение сообщения**: Пользователь отправляет сообщение в Telegram
3. **Обработка контекста**: Бот формирует контекст с системным промптом и историей диалога
4. **Генерация ответа**: LLM генерирует ответ в соответствии с заданной ролью
5. **Возврат ответа**: Ответ возвращается пользователю через Telegram
6. **Сохранение истории**: Сообщения сохраняются для поддержания контекста

### Примеры использования

**Сценарий 1: Проверка роли**
```
Пользователь: /role
Бот: 🎭 Моя роль: Python-эксперт
     [Детальное описание роли]
```

**Сценарий 2: Работа в рамках роли**
```
Пользователь: Как оптимизировать этот код?
Бот: [Анализирует код и дает рекомендации в роли Python-эксперта]
```

**Сценарий 3: Запрос вне роли**
```
Пользователь: Помоги с JavaScript
Бот: Извините, я специализируюсь на Python. 
     Для JavaScript вам нужен другой специалист.
```
