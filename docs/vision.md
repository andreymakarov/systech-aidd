# Техническое видение проекта: LLM-ассистент

## Описание

Минималистичный Telegram-бот с интеграцией LLM для проверки концепции. Следует принципам KISS и ООП без избыточной инженерии.

---

## 1. Технологии

### Core
- **Python 3.11+** - основной язык разработки
- **uv** - управление зависимостями и виртуальными окружениями

### Telegram Bot
- **aiogram 3.x** - асинхронный фреймворк для Telegram Bot API
- **polling** - метод получения обновлений (без вебхуков)

### LLM Integration
- **openai** (официальный Python client) - для работы с OpenRouter API
- **OpenRouter** - провайдер доступа к различным LLM

### Development Tools
- **make** - автоматизация задач (запуск, тесты, установка зависимостей)
- **python-dotenv** - для загрузки переменных окружения из .env файла
- **logging** (стандартный модуль) - для логирования

---

## 2. Принципы разработки

### KISS (Keep It Simple, Stupid)
- Минимальный функционал для проверки идеи
- Никаких избыточных абстракций
- Прямолинейная реализация без "на будущее"

### ООП с ограничениями
- **1 класс = 1 файл** (строго)
- Простая иерархия классов без глубокой вложенности
- Композиция предпочтительнее наследования

### Дополнительные принципы
- **Явное лучше неявного** - понятный код без магии
- **Fail fast** - ошибки конфигурации должны обнаруживаться при старте
- **Минимум зависимостей** - только необходимое
- **Асинхронность** - используем async/await для работы с IO

### Что НЕ делаем на этапе MVP
- ❌ База данных (история только в памяти)
- ❌ Middleware цепочки (только если критически необходимо)
- ❌ Сложная обработка ошибок (базовая обработка и логирование)
- ❌ Метрики и мониторинг
- ❌ Тесты

## 4. Архитектура проекта

### Компоненты и их взаимодействие

```
User (Telegram) 
    ↓↑
TelegramBot (aiogram dispatcher + polling)
    ↓↑
MessageHandler
    ↓ (получает сообщение)
    ↓ (запрашивает историю) → ConversationManager
    ↓ (получает историю)
    ↓ (отправляет запрос) → LLMClient → OpenRouter API
    ↓ (получает ответ)
    ↓ (сохраняет в историю) → ConversationManager
    ↓ (возвращает ответ)
TelegramBot
    ↓
User (Telegram)
```

### Описание потока данных

1. **TelegramBot** получает update через polling
2. **MessageHandler** обрабатывает текстовое сообщение
3. **ConversationManager** предоставляет историю диалога для user_id
4. **LLMClient** формирует запрос к LLM (system prompt + история)
5. Ответ от LLM сохраняется в историю через **ConversationManager**
6. Ответ отправляется пользователю через **TelegramBot**

### Инициализация приложения

```
__main__.py
  → Config.load() - загрузка и валидация настроек
  → ConversationManager() - создание менеджера истории
  → LLMClient(config) - создание клиента LLM
  → MessageHandler(conversation_manager, llm_client) - создание обработчика
  → TelegramBot(config, message_handler) - создание и запуск бота
```

### Обрабатываемые команды

- `/start` - приветственное сообщение
- `/clear` - очистка истории диалога пользователя

### Принципы архитектуры

- **Dependency Injection** - зависимости передаются через конструктор
- **Stateless handlers** - вся state в ConversationManager
- **Graceful shutdown** - корректная остановка по Ctrl+C

## 5. Модель данных

### Структура данных в памяти (ConversationManager)

```python
# Хранилище в памяти
conversations: dict[int, list[dict]]
```

**Ключ:** `user_id` (int) - Telegram user ID

**Значение:** список сообщений в формате OpenAI API:
```python
[
    {"role": "user", "content": "Привет!"},
    {"role": "assistant", "content": "Здравствуйте! Чем могу помочь?"},
    {"role": "user", "content": "Расскажи о себе"},
    {"role": "assistant", "content": "Я AI-ассистент..."}
]
```

### Операции ConversationManager

- `get_history(user_id: int) -> list[dict]` - получить историю пользователя
- `add_message(user_id: int, role: str, content: str)` - добавить сообщение
- `clear_history(user_id: int)` - очистить историю пользователя

### Формат запроса к LLM

```python
messages = [
    {"role": "system", "content": SYSTEM_PROMPT},
    *conversation_history,  # история пользователя
    {"role": "user", "content": user_message}
]
```

### System Prompt по умолчанию

```
Ты - полезный AI-ассистент. Отвечай на вопросы пользователя четко и по существу.
```

### Особенности

- История не сохраняется между перезапусками
- Контекст не ограничивается (до лимитов модели)
- Каждый пользователь имеет изолированную историю
- Метаданные (timestamp, message_id) не хранятся

## 6. Работа с LLM

### Конфигурация LLMClient

```bash
OPENROUTER_API_KEY      # API ключ
OPENROUTER_MODEL        # openai/gpt-4o-mini (по умолчанию)
OPENROUTER_BASE_URL     # https://openrouter.ai/api/v1
```

### Использование OpenAI client

```python
from openai import AsyncOpenAI

client = AsyncOpenAI(
    api_key=config.openrouter_api_key,
    base_url=config.openrouter_base_url
)
```

### Метод генерации ответа

```python
async def generate_response(messages: list[dict]) -> str:
    response = await client.chat.completions.create(
        model=config.model,
        messages=messages
    )
    return response.choices[0].message.content
```

### Обработка ошибок

- Ошибки API логируются
- Пользователю возвращается понятное сообщение об ошибке
- Бот продолжает работать (не падает)

### Параметры генерации

- `temperature` - по умолчанию (дефолт модели)
- `max_tokens` - по умолчанию (дефолт модели)
- Streaming - **не используется** (для простоты)

## 7. Сценарии работы

### Сценарий 1: Первый запуск

1. Пользователь запускает бота → `/start`
2. Бот отправляет приветственное сообщение:
   ```
   Привет! Я AI-ассистент. Задай мне любой вопрос!
   
   Доступные команды:
   /start - приветствие
   /clear - очистить историю диалога
   ```
3. История для пользователя создается автоматически (пустая)

### Сценарий 2: Обычный диалог

1. Пользователь отправляет текстовое сообщение
2. Бот показывает "печатает..." (typing action)
3. Сообщение добавляется в историю пользователя
4. Отправляется запрос в LLM (system prompt + история)
5. Ответ LLM добавляется в историю
6. Ответ отправляется пользователю
7. История сохраняется в памяти для следующих сообщений

### Сценарий 3: Очистка истории

1. Пользователь отправляет `/clear`
2. История диалога удаляется
3. Бот отправляет подтверждение: `История диалога очищена`
4. Следующие сообщения начинают новый контекст

### Сценарий 4: Ошибка LLM API

1. Ошибка при вызове API
2. Ошибка логируется
3. Пользователю отправляется: `Произошла ошибка при обработке запроса. Попробуйте позже.`
4. История не обновляется (сообщение пользователя не добавляется)

### Сценарий 5: Перезапуск бота

1. Бот перезапускается
2. Вся история диалогов теряется
3. Пользователи начинают с чистого листа

### Сценарий 6: Нетекстовые сообщения

1. Пользователь отправляет фото, файл, стикер и т.д.
2. Бот отвечает: `Я работаю только с текстовыми сообщениями`
3. Сообщение игнорируется

## 8. Подход к конфигурированию

### Конфигурация через переменные окружения

Все настройки в файле `.env`:

```bash
# Telegram Bot
TELEGRAM_BOT_TOKEN=your_bot_token_here

# OpenRouter
OPENROUTER_API_KEY=your_api_key_here
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
OPENROUTER_MODEL=openai/gpt-4o-mini

# System Prompt
SYSTEM_PROMPT=Ты - полезный AI-ассистент. Отвечай на вопросы пользователя четко и по существу.
```

### Класс Config

- Загружает переменные через `python-dotenv`
- Валидирует обязательные параметры при старте
- Падает с понятной ошибкой, если что-то не настроено (Fail Fast)
- Предоставляет типизированный доступ к настройкам

### Обязательные параметры

- `TELEGRAM_BOT_TOKEN` - обязательный
- `OPENROUTER_API_KEY` - обязательный

### Параметры по умолчанию

- `OPENROUTER_BASE_URL` - `https://openrouter.ai/api/v1`
- `OPENROUTER_MODEL` - `openai/gpt-4o-mini`
- `SYSTEM_PROMPT` - универсальный промпт (см. выше)

### Файл .env.example

Предоставляется шаблон `.env.example` для быстрого старта с комментариями.

## 9. Подход к логгированию

### Использование стандартного logging

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s'
)
```

### Что логируем

**INFO уровень:**
- Запуск бота
- Остановка бота
- Получено сообщение от пользователя (user_id, длина текста)
- Отправлен ответ пользователю (user_id, длина ответа)
- Выполнение команд (/start, /clear)

**ERROR уровень:**
- Ошибки при вызове OpenRouter API
- Ошибки при отправке сообщений в Telegram
- Критические ошибки конфигурации

### Что НЕ логируем

- Полный текст сообщений пользователей (приватность)
- Полный текст ответов LLM
- API ключи и токены

### Формат логов

Простой текстовый формат с timestamp:
```
2025-10-10 15:30:45 - bot.handlers - INFO - User 12345 sent message (120 chars)
2025-10-10 15:30:47 - bot.llm_client - INFO - LLM response received (450 chars)
2025-10-10 15:30:47 - bot.handlers - INFO - Response sent to user 12345
```

### Вывод логов

- В консоль (stdout)
- Без записи в файлы (для MVP)
- Фиксированный уровень INFO
