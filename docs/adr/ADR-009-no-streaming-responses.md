# ADR-009: Отказ от streaming ответов LLM

## Статус

Принято (Accepted)

## Контекст

OpenAI API (и OpenRouter) поддерживает два режима получения ответов:
1. **Обычный режим** - получение полного ответа целиком
2. **Streaming режим** - получение ответа частями (по мере генерации)

Streaming улучшает UX (пользователь видит ответ сразу), но усложняет код.

## Решение

**Не использовать streaming** для ответов LLM на этапе MVP.

### Обоснование

1. **Простота реализации** - один API вызов вместо обработки потока
2. **Меньше кода** - не нужна логика обработки частей ответа
3. **Меньше багов** - нет edge cases с обрывом потока
4. **Достаточный UX** - для коротких ответов задержка приемлема
5. **KISS принцип** - минимальная сложность для MVP

### Поведение

1. Пользователь отправляет сообщение
2. Бот показывает "печатает..." (typing action)
3. Ожидание полного ответа от LLM
4. Отправка ответа пользователю целиком

## Последствия

### Положительные
- ✅ Максимально простой код
- ✅ Меньше потенциальных багов
- ✅ Не нужна логика обновления сообщений
- ✅ Проще обработка ошибок
- ✅ Легче отладка

### Отрицательные
- ⚠️ Пользователь ждет весь ответ целиком
- ⚠️ Для длинных ответов ожидание может быть заметным
- ⚠️ Нет интерактивности во время генерации

### UX компромисс

**Приемлемо для MVP:**
- Модель GPT-4o Mini генерирует быстро (обычно 2-5 секунд)
- Typing action показывает, что бот работает
- Для коротких диалогов задержка незаметна

**Неприемлемо для:**
- Очень длинных ответов (несколько параграфов)
- Медленных моделей
- Production версии с высокими требованиями к UX

### Возможность изменения

В будущем легко добавить streaming:

```python
# Было (non-streaming)
response = await client.chat.completions.create(...)
return response.choices[0].message.content

# Станет (streaming)
stream = await client.chat.completions.create(stream=True, ...)
async for chunk in stream:
    # Обновляем сообщение в Telegram
    ...
```

Aiogram поддерживает `edit_message_text()` для обновления сообщения.

## Альтернативы

1. **Streaming с обновлением каждые N символов** - отклонено (усложнение для MVP)
2. **Streaming только для длинных ответов** - отклонено (преждевременная оптимизация)
3. **Fake streaming (имитация)** - отклонено (бессмысленное усложнение)
