# ADR-002: Использование Polling вместо Webhooks

## Статус

Принято (Accepted)

## Контекст

Telegram Bot API поддерживает два способа получения обновлений:
1. **Polling** - бот периодически опрашивает API на наличие новых сообщений
2. **Webhooks** - Telegram отправляет обновления на указанный URL

Необходимо выбрать метод для MVP.

## Решение

Использовать **polling** для получения обновлений от Telegram.

### Обоснование

1. **Простота настройки**
   - Не требуется публичный IP или домен
   - Не нужен SSL сертификат
   - Нет необходимости в веб-сервере

2. **Быстрая разработка**
   - Запуск на локальной машине
   - Простая отладка
   - Нет сложностей с инфраструктурой

3. **Достаточно для MVP**
   - Небольшая нагрузка на этапе проверки концепции
   - Задержка в 1-2 секунды приемлема

## Последствия

### Положительные
- ✅ Запуск на любой машине (даже за NAT)
- ✅ Не нужна инфраструктура для webhooks
- ✅ Простая отладка и тестирование
- ✅ Быстрый старт разработки

### Отрицательные
- ⚠️ Небольшая задержка в получении сообщений (1-2 сек)
- ⚠️ Постоянное соединение с Telegram API
- ⚠️ Не масштабируется для высоких нагрузок

### Возможность изменения

При необходимости масштабирования в будущем легко перейти на webhooks - aiogram поддерживает оба режима с минимальными изменениями кода.

## Альтернативы

**Webhooks** - отклонены для MVP по причине избыточной сложности инфраструктуры.
