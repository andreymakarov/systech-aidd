# ADR-003: Хранение истории диалогов в памяти

## Статус

Принято (Accepted)

## Контекст

Бот должен поддерживать контекст диалога для каждого пользователя. Необходимо решить, где хранить историю сообщений:
- В базе данных (PostgreSQL, SQLite, MongoDB и т.д.)
- В файловой системе
- В памяти приложения

## Решение

Хранить историю диалогов **в памяти приложения** (RAM) без персистентности.

### Структура данных

```python
conversations: dict[int, list[dict]] = {}
# Ключ: user_id (Telegram ID)
# Значение: список сообщений в формате OpenAI API
```

### Характеристики

- История создается автоматически при первом сообщении пользователя
- История хранится до перезапуска бота
- Каждый пользователь имеет изолированную историю
- Контекст не ограничивается количеством сообщений

## Последствия

### Положительные
- ✅ Максимальная простота реализации
- ✅ Нулевая настройка (не нужна БД)
- ✅ Высокая скорость доступа к данным
- ✅ Не требуется миграции и схемы данных
- ✅ Следует принципу KISS

### Отрицательные
- ⚠️ История теряется при перезапуске бота
- ⚠️ Использование RAM растет с количеством пользователей
- ⚠️ Нет персистентности данных
- ⚠️ Нет возможности аналитики истории

### Приемлемость для MVP

Для проверки концепции потеря истории при перезапуске **приемлема**:
- Быстрая проверка идеи
- Небольшое количество пользователей
- Фокус на функциональности, а не на надежности хранения

### Возможность изменения

В будущем легко добавить персистентное хранилище:
1. Добавить слой абстракции (Repository pattern)
2. Реализовать хранение в SQLite/PostgreSQL
3. Изменить только класс ConversationManager

## Альтернативы

1. **SQLite** - отклонена как избыточная для MVP
2. **PostgreSQL/MongoDB** - отклонены как серьезное усложнение
3. **JSON файлы** - отклонены (усложнение без значимой пользы для MVP)
