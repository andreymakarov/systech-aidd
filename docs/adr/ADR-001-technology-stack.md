# ADR-001: Выбор технологического стека

## Статус

Принято (Accepted)

## Контекст

Необходимо выбрать технологический стек для разработки MVP Telegram-бота с интеграцией LLM. Требуется максимально простое и быстрое решение для проверки концепции.

## Решение

Выбран следующий технологический стек:

### Core
- **Python 3.11+** - основной язык разработки
  - Широкая поддержка библиотек для работы с AI/LLM
  - Простой синтаксис, быстрая разработка
  - Хорошая асинхронная поддержка (asyncio)

- **uv** - управление зависимостями и виртуальными окружениями
  - Современный, быстрый инструмент
  - Замена pip + virtualenv
  - Простота использования

### Telegram Bot
- **aiogram 3.x** - асинхронный фреймворк для Telegram Bot API
  - Нативная поддержка async/await
  - Современный API
  - Хорошая документация

### LLM Integration
- **openai** (официальный Python client) - для работы с OpenRouter API
  - Стандартный клиент, совместимый с OpenRouter
  - Асинхронная поддержка
  - Простой API

- **OpenRouter** - провайдер доступа к различным LLM
  - Единый интерфейс для множества моделей
  - Гибкое ценообразование
  - Совместимость с OpenAI API

### Development Tools
- **make** - автоматизация задач
  - Простота использования
  - Стандартный инструмент
  - Кроссплатформенность

- **python-dotenv** - загрузка переменных окружения
  - Стандартная практика для конфигурации
  - Безопасность (не коммитим .env)

- **logging** (стандартный модуль) - логирование
  - Встроен в Python
  - Достаточен для MVP
  - Не требует дополнительных зависимостей

## Последствия

### Положительные
- ✅ Минимальное количество зависимостей
- ✅ Быстрая разработка благодаря Python и aiogram
- ✅ Гибкость выбора LLM моделей через OpenRouter
- ✅ Асинхронность из коробки (aiogram + openai)
- ✅ Низкий порог входа для разработчиков

### Отрицательные
- ⚠️ Python медленнее компилируемых языков (не критично для бота)
- ⚠️ uv - относительно новый инструмент (но стабильный)

### Риски
- OpenRouter может изменить API (низкая вероятность, т.к. следует OpenAI стандарту)
