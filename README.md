# Systech AIDD - LLM-ассистент для Telegram

Минималистичный Telegram-бот с интеграцией LLM для проверки концепции. Следует принципам KISS и ООП без избыточной инженерии.

## Возможности

✅ Ответы на вопросы через LLM (OpenRouter API)  
✅ Поддержка контекста диалога для каждого пользователя  
✅ Настраиваемая роль бота через файл конфигурации  
✅ Очистка истории диалога по команде  
✅ Асинхронная архитектура  
✅ Простая и понятная кодовая база (1 класс = 1 файл)  
✅ Покрытие тестами 97%

## Требования

- Python 3.11+
- [uv](https://github.com/astral-sh/uv) - менеджер зависимостей
- Telegram Bot Token
- OpenRouter API Key

## Быстрый старт

### 1. Установка зависимостей

```bash
make install
```

Или напрямую через uv:
```bash
uv sync
```

### 2. Получение токенов

#### Telegram Bot Token
1. Откройте [@BotFather](https://t.me/botfather) в Telegram
2. Отправьте команду `/newbot`
3. Следуйте инструкциям для создания бота
4. Скопируйте полученный токен

#### OpenRouter API Key
1. Зарегистрируйтесь на [OpenRouter](https://openrouter.ai/)
2. Перейдите в [Keys](https://openrouter.ai/keys)
3. Создайте новый API ключ
4. Скопируйте ключ

### 3. Настройка

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Отредактируйте `.env` и заполните обязательные параметры:

```bash
# Обязательные параметры
TELEGRAM_BOT_TOKEN=your_bot_token_here
OPENROUTER_API_KEY=your_api_key_here

# Необязательные параметры (значения по умолчанию)
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
OPENROUTER_MODEL=openai/gpt-4o-mini
ROLE_PROMPT_FILE=prompts/role.txt
```

### 4. Запуск

```bash
make run
```

Или напрямую:
```bash
uv run python -m src.bot
```

Для остановки нажмите `Ctrl+C` - бот корректно завершит работу.

## Использование

### Команды бота

- `/start` - приветствие и справка по командам
- `/role` - показать текущую роль бота
- `/clear` - очистить историю диалога и начать с чистого листа

### Примеры использования

1. **Простой вопрос:**
   ```
   Пользователь: Привет! Как дела?
   Бот: Здравствуйте! У меня всё хорошо, спасибо! Чем могу помочь?
   ```

2. **Контекстный диалог:**
   ```
   Пользователь: Расскажи о Python
   Бот: Python - это высокоуровневый язык программирования...
   
   Пользователь: А для чего он используется?
   Бот: Python используется для веб-разработки, анализа данных...
   ```

3. **Просмотр роли:**
   ```
   Пользователь: /role
   Бот: 🎭 **Моя роль:**
        
        Ты - полезный AI-ассистент...
   ```

4. **Очистка истории:**
   ```
   Пользователь: /clear
   Бот: История диалога очищена
   
   Пользователь: Привет
   Бот: [отвечает без контекста предыдущего диалога]
   ```

### Особенности

- **Контекст диалога**: бот помнит всю историю беседы
- **Изолированные пользователи**: каждый пользователь имеет свою независимую историю
- **Только текст**: бот работает только с текстовыми сообщениями (фото, файлы игнорируются)
- **История в памяти**: история теряется при перезапуске бота (по дизайну MVP)

## Архитектура

Проект следует принципу **1 класс = 1 файл** и использует Dependency Injection:

```
Config → ConversationManager, LLMClient → MessageHandler → TelegramBot
```

### Модули

- `config.py` - валидация и загрузка конфигурации
- `conversation.py` - управление историей диалогов в памяти
- `llm_client.py` - взаимодействие с OpenRouter API
- `role_manager.py` - управление ролью бота из файла
- `handlers.py` - обработка сообщений и команд
- `bot.py` - инициализация и запуск Telegram бота
- `__main__.py` - точка входа приложения

### Настройка роли бота

Роль бота определяется в файле `prompts/role.txt`. Вы можете изменить содержимое этого файла, чтобы кастомизировать поведение бота:

```txt
Ты - профессиональный AI-ассистент, специализирующийся на помощи программистам.

Твои задачи:
- Отвечать на технические вопросы четко и по существу
- Предоставлять примеры кода с пояснениями
- Помогать с отладкой и рефакторингом

Стиль общения: дружелюбный, но профессиональный.
```

Чтобы использовать другой файл с ролью, установите переменную окружения:
```bash
ROLE_PROMPT_FILE=prompts/custom_role.txt
```

## Обработка ошибок

- **Ошибки конфигурации**: бот не запустится, выведет понятное сообщение
- **Ошибки LLM API**: пользователь получит сообщение об ошибке, бот продолжит работать
- **Graceful shutdown**: при `Ctrl+C` бот корректно завершит все соединения
