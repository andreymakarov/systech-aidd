# Ревью проекта на соответствие соглашениям

## Цель
Провести комплексную проверку проекта на соответствие всем установленным соглашениям и стандартам.

## Инструкции

### 1. Изучение соглашений
- Прочитай все файлы соглашений в директории `.cursor/rules/*.mdc`
- Изучи файл `docs/vision.md` с техническим видением проекта
- Запомни все правила, принципы и требования к коду

### 2. Проведение ревью
Проверь соответствие проекта по следующим категориям:

#### Архитектура и структура
- Соответствие организации файлов и директорий установленным правилам
- Правильность разделения ответственности между модулями
- Соблюдение архитектурных принципов из vision.md

#### Качество кода
- Следование стандартам именования
- Соблюдение принципов SOLID, DRY, KISS
- Правильное использование type hints
- Отсутствие code smells и антипаттернов

#### Документация
- Наличие необходимых docstrings
- Актуальность комментариев
- Соответствие документации реальной реализации

#### Тестирование
- Покрытие кода тестами
- Качество и изоляция тестов
- Соблюдение принципов тестирования из соглашений

#### Автоматизация и инструменты
- Использование инструментов контроля качества
- Соблюдение правил форматирования
- Прохождение линтеров и type checking

#### Соблюдение workflow
- Следование установленным процессам разработки
- Правильность коммитов и веток (если применимо)

### 3. Формирование отчета
Создай структурированный отчет в следующем формате:

```markdown
# Отчет о ревью проекта

**Дата:** [текущая дата]
**Проверенные соглашения:** [список проверенных .mdc файлов]

## Резюме
[Краткая общая оценка соответствия проекта соглашениям]

## Детальные результаты

### ✅ Соблюдается
[Перечисли, что выполнено правильно, по категориям]

### ⚠️ Требует внимания
[Перечисли незначительные отклонения и рекомендации по улучшению]

### ❌ Нарушения
[Перечисли критические нарушения соглашений с указанием конкретных файлов и строк]

## Рекомендации
[Приоритизированный список действий для приведения проекта в соответствие]

## Общая оценка
[Оценка соответствия: Отлично / Хорошо / Требует доработки / Критично]
```

### 4. Вывод отчета
- Выведи полный отчет в чат для ознакомления пользователя
- Объясни основные находки и рекомендации

### 5. Сохранение отчета
- Спроси у пользователя, нужно ли сохранить отчет
- При подтверждении:
  - Создай директорию `docs/reviews/`, если её нет
  - Найди последний номер файла ревью (review-NNN.md)
  - Сохрани отчет с следующим порядковым номером
  - Формат имени: `review-001.md`, `review-002.md` и т.д.

## Важно
- Будь объективным и конструктивным
- Приводи конкретные примеры нарушений с указанием файлов
- Предлагай практичные решения, а не только критикуй
- Разделяй критичные проблемы и мелкие улучшения
- Признавай хорошо выполненные аспекты проекта
