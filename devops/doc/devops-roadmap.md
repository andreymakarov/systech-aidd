# DevOps Roadmap

## Описание

MVP DevOps roadmap для проекта Systech AIDD. Цель: пройти путь от локального запуска до автоматического развертывания на удаленный сервер максимально быстро, следуя принципам простоты и скорости без преждевременной оптимизации.

## Принципы

- **MVP подход**: фокус на простоте и скорости
- **Итеративность**: небольшие спринты с четкими целями
- **Автоматизация**: от ручных процессов к автоматическим
- **Документирование**: каждый спринт имеет план реализации

## Спринты

### D0: Basic Docker Setup

**Цель:** Запустить все сервисы (Bot, Backend, Frontend) локально через docker-compose одной командой.

**Состав работ:**
- Создать Dockerfile для frontend (для backend и bot уже существуют)
- Переместить существующие Dockerfile в директорию `devops/`
- Обновить docker-compose.yml для работы с 3 сервисами
- Создать `.dockerignore` файлы для каждого сервиса
- Настроить volume для `backend/data/bot.db`
- Настроить чтение `.env` файла
- Проверить работоспособность: `docker-compose up` - всё работает локально
- Обновить README.md с инструкциями по запуску через Docker

**Планирование:** Детальное планирование выполняется в режиме Plan Mode перед началом спринта.

**После завершения:** Добавить ссылку на план реализации в таблицу прогресса.

---

### D1: Build & Publish

**Цель:** Автоматическая сборка и публикация Docker образов в GitHub Container Registry при push в main ветку.

**Состав работ:**
- Создать GitHub Actions workflow `.github/workflows/build.yml`
- Настроить trigger на push в main ветку
- Реализовать сборку 3 образов (bot, backend, frontend)
- Настроить публикацию в ghcr.io с тегом `latest`
- Создать инструкцию по настройке permissions для GitHub Container Registry
- Добавить badges статуса сборки в README.md

**Планирование:** Детальное планирование выполняется в режиме Plan Mode перед началом спринта.

**После завершения:** Добавить ссылку на план реализации в таблицу прогресса.

---

### D2: Развертывание на сервер

**Цель:** Развернуть приложение на удаленном сервере вручную с использованием пошаговой инструкции.

**Контекст:** 
- Предоставлен готовый сервер (адрес + SSH ключ)
- Docker уже установлен на сервере

**Состав работ:**
- Создать пошаговую инструкцию для ручного деплоя (`doc/guides/manual-deploy.md`)
- Описать процесс SSH подключения с использованием SSH ключа
- Инструкции по копированию docker-compose.yml и .env на сервер
- Описать процесс docker login к ghcr.io
- Инструкции по загрузке образов (docker-compose pull)
- Инструкции по запуску сервисов (docker-compose up -d)
- Описать запуск миграций базы данных
- Создать шаблон `.env.production` с описанием всех переменных
- Создать скрипт проверки работоспособности (`scripts/deploy-check.sh`)

**Планирование:** Детальное планирование выполняется в режиме Plan Mode перед началом спринта.

**После завершения:** Добавить ссылку на план реализации в таблицу прогресса.

---

### D3: Auto Deploy

**Цель:** Автоматическое развертывание на сервер через GitHub Actions по ручному запуску (workflow_dispatch).

**Состав работ:**
- Создать GitHub Actions workflow `.github/workflows/deploy.yml`
- Настроить trigger на ручной запуск (workflow_dispatch)
- Реализовать SSH подключение к серверу с использованием SSH ключа
- Автоматическая загрузка новых версий образов (pull)
- Автоматический перезапуск сервисов через docker-compose
- Создать инструкцию по настройке GitHub secrets (SSH_KEY, HOST, USER)
- Добавить уведомления о статусе деплоя
- Добавить кнопку "Deploy" в README.md

**Планирование:** Детальное планирование выполняется в режиме Plan Mode перед началом спринта.

**После завершения:** Добавить ссылку на план реализации в таблицу прогресса.

## Workflow выполнения спринта

1. **Планирование** - активировать Plan Mode и согласовать детальный план спринта
2. **Реализация** - выполнить задачи согласно плану
3. **Тестирование** - проверить работоспособность
4. **Документирование** - обновить документацию и README
5. **Обновление прогресса** - обновить статус в таблице и добавить ссылку на план
6. **Коммит** - зафиксировать изменения

## Зависимости между спринтами

```
D0 (Docker Setup)
    ↓
D1 (Build & Publish)
    ↓
D2 (Manual Deploy)
    ↓
D3 (Auto Deploy)
```

Каждый следующий спринт зависит от предыдущего. Необходимо выполнять последовательно.
